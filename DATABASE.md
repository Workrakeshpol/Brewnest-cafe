The BrewNest database is built with **PostgreSQL** and managed via **Prisma**. Below is a high‑level overview of the major entities and their relationships:

| Entity | Primary Key | Key Relationships |
|--------|-------------|-------------------|
| **User** | `id` (UUID) | One‑to‑many → `Order`, `Reservation`, `Address`, `LoyaltyAccount`, `Review`, `Favorite` |
| **MenuCategory** | `id` | One‑to‑many → `MenuItem` |
| **MenuItem** | `id` | Many‑to‑one → `MenuCategory`; One‑to‑many → `ItemVariant`, `ItemTag`, `OrderItem`, `Favorite`, `Review` |
| **Order** | `id` | Many‑to-one → `User`; One‑to‑many → `OrderItem`, `Payment` |
| **OrderItem** | `id` | Many‑to-one → `Order`; Many‑to-one → `MenuItem` |
| **Payment** | `id` | Many‑to-one → `Order` |
| **Reservation** | `id` | Many‑to-one → `User` (optional); Many‑to-one → `CafeTable` |
| **CafeTable** | `id` | One‑to‑many → `Reservation` |
| **LoyaltyTier** | `id` | One‑to‑many → `LoyaltyAccount` |
| **LoyaltyAccount** | `id` | One‑to‑one → `User`; Many‑to‑one → `LoyaltyTier`; One‑to‑many → `LoyaltyTransaction` |
| **LoyaltyTransaction** | `id` | Many‑to-one → `LoyaltyAccount`; Many‑to-one → `Order` (optional) |
| **PromoCode** | `id` | One‑to‑many → `PromoUsage` |
| **PromoUsage** | `id` | Many‑to-one → `PromoCode`; Many‑to-one → `User`; Many‑to-one → `Order` |
| **Favorite** | `id` | Many‑to-one → `User`; Many‑to-one → `MenuItem` |
| **Review** | `id` | Many‑to-one → `User`; Many‑to-one → `MenuItem`; Many‑to-one → `Order` (optional) |

## Schema Explanation
- All tables use **UUID** primary keys generated by `gen_random_uuid()`.
- Timestamps (`createdAt`, `updatedAt`) are automatically set via Prisma default `now()`.
- Soft‑delete is implemented on `User` and `MenuItem` via the `isActive` boolean flag.
- Auditing fields (`lastLoginAt`, `updatedAt`) help with analytics and security.
- Enum‑style columns (e.g., `role`, `orderStatus`, `promoType`) are stored as `VARCHAR` with application‑level validation via Zod.

## Migration Process
1. **Generate a migration** after modifying the Prisma schema:
   ```bash
   cd server
   npx prisma migrate dev --name <description>
   ```
   This creates a SQL migration in `prisma/migrations/` and updates the local dev DB.
2. **Apply migrations to other environments** (staging / production):
   ```bash
   npx prisma migrate deploy   # runs pending migrations
   ```
   The command is also available via the npm script `npm run db:migrate`.
3. **Version control** – keep the `prisma/schema.prisma` and migration folders committed.

## Seed Process
A seed script populates essential reference data (menu categories, demo users, loyalty tiers, promo codes).
```bash
cd server
npm run db:seed   # runs src/database/seeds/seed.ts
```
- The script is idempotent – it checks for existing records before inserting.
- Seed data is also used by the QA suite to create deterministic test accounts.
